## Shipped (prototype, October 2026)

- [x] 1. **Real-world map pipeline** - OpenStreetMap and SRTM converted to `world.json` and `heightmap.json` by the Python tools
- [x] 2. **Generated suburb** - terrain, roads with markings and street lights, houses from outlines, fields, fences, streams, signs, parked cars
- [x] 3. **Player on foot** - walk, sprint, jump, aim, shoot, reload, two weapons, slow-motion aiming, stamina
- [x] 4. **Driving** - cars and taxis on vehicle physics, enter and exit, chase camera, lights, horn, call the car back
- [x] 5. **NPCs and factions** - residents, police and gang with wander, patrol, alert, combat and death
- [x] 6. **Dialogue** - JSON conversation trees with conditions and actions
- [x] 7. **Missions** - goto, kill_group, talk and return steps, spawns, rewards, HUD marker
- [x] 8. **Wanted system** - witnesses, heat levels, decay, admission-of-guilt fine
- [x] 9. **Day, night and weather** - sun, moon, fog, lamps, five weather states
- [x] 10. **UI** - HUD, minimap, world map with waypoints and location names, pause menu, settings, graphics tiers
- [x] 11. **Save and load** - single slot in `user://save.json`
- [x] 12. **Per-building overrides** - roof, wall, facade photo or 3D model by OpenStreetMap id

## MVP: SOLID without breaking the game

- [x] 14. **Unit test runner** - `tests/Veld.Tests` (xUnit) for pure logic, wired into the build and documented in `AGENTS.md`
- [x] 15. **Game services seam** - the mission, dialogue and wanted systems stop reaching into the `Game` singleton; each receives small ports (economy, notifier, clock, world query, dialogue view) with live adapters in the game and in-memory fakes in tests
  - [x] 15a. **Ports and the mission system** - `IEconomy`, `INotifier`, `IWorldQuery`, `INpcView`, `IPlayerView` with live adapters; `MissionManager` on the ports; first behaviour tests with fakes
  - [x] 15b. **Dialogue on the ports** - `IClock` and `IDialogueView` added; `DialogueSystem` conditions and actions tested with fakes
  - [x] 15c. **Wanted system on the ports** - `WantedSystem` heat, witnesses and decay tested with a fake world
- [x] 16. **Mission step registry** - `IMissionStep` implementations looked up by type name replace the switches in `MissionManager`; existing JSON unchanged
- [x] 17. **Dialogue action and condition registries** - the same treatment for `DialogueSystem.Holds` and `Apply`
- [x] 18. **Retire the Game singleton** - remaining `Game.Instance` call sites replaced with services composed in `Main`, UI first, then World, then Characters
  - [x] 18a. **Services carved out of Game** - `Settings`, `Notifier`, `Purse`, `Reputation`, `UiState` and `SaveGame` as small classes that `Game` owns and forwards to; the gameplay systems receive the real ones; no call site moves yet
  - [x] 18b. **UI off the singleton** - `Hud`, `Minimap`, `DialogueBox`, `PauseMenu` and `WorldMap` receive their services and siblings through `Init` from `Main` (32 sites)
  - [x] 18c. **World and audio off the singleton** - `Terrain`, `RoadBuilder`, `FootprintBuilder`, `WorldBuilder`, `DayNight`, `Weather` and `Sfx`; `DeadNpcs` moves into `WorldBuilder` (13 sites)
  - [x] 18d. **Player and camera off the singleton** - `Player` and `CameraRig` (26 sites)
  - [x] 18e. **NPCs, horse and vehicles off the singleton** - `Npc`, `Horse` and `Vehicle` (36 sites)
  - [x] 18f. **Delete the autoload** - `Main` loads the data and composes every service and system, the live adapters read `Main`, the dev harnesses follow, `Game.cs` and the autoload entry go; `Game.Instance` appears nowhere (12 sites)
- [x] 19. **Simulation and presentation split** - a `Veld.Sim` library holding world, mission, NPC and economy state at a fixed tick; Godot nodes render and forward input
  - [x] 19a. **The Veld.Sim library** - a class library under `sim/Veld.Sim/` holding the code that already has no node dependency: the data model and loader behind a file port, money, factions, the ports, purse, standing, notifier, missions, dialogue and wanted; `Veld.Sim` namespaces; the game and the tests reference it
  - [x] 19b. **The Simulation object and the fixed tick** - one `Simulation` owning the purse, standing, clock, missions, wanted and dialogue, ticked from `Main` at the physics rate; `DayNight` renders the sim clock; save and load read the simulation
  - [x] 19c. **NPC decisions in the simulation** - hostility, the state machine, targets, shots and loot as a character brain in `Veld.Sim`, tested; the `Npc` node becomes body and view
  - [x] 19d. **Player state in the simulation** - `PlayerState` and `WeaponState` in `Veld.Sim.Characters`: health and regen, stamina, the dead eye meter, weapons and ammo with reload and cooldown, mount and drive state, death and respawn; the `Player` node becomes body and view and both bodies share one shot raycast
  - [x] 19e. **The save as a snapshot of the simulation** - `Simulation.Snapshot` and `Restore` over purse, standing, clock, missions, wanted, the player's state and the dead characters; `SaveGame` serialises the snapshot and only moves the player's body; `WorldBuilder.DeadNpcs` retired; the prerequisite for multiplayer
