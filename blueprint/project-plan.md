## 1. Problem - What problem are we solving?

Veld is an open-world game set in Montford, Unit 7 of Chatsworth, Durban, built
from real map data so that people who know the place can walk and drive their
own streets. The code was written in one day as a prototype. It works, but it
hangs off one global singleton, routes behaviour through string switches, has
no unit tests and runs only on Windows desktop. The job now is to turn that
prototype into a clean, testable, scalable codebase without breaking the game,
then grow it into something that can ship on phones and later support
multiplayer.

## 2. Users - Who is this for?

- The owner, as developer and first player.

## 3. Features - What does the MVP need?

Shipped in the prototype:

- Real suburb from OpenStreetMap and SRTM elevation: 760 roads, 14,405 building
  outlines, sports fields, parks, parking, fences, walls, streams, 45 points of
  interest, on a 3100 m square map
- Houses generated from their outlines: brick or plaster walls, tile or iron hip
  roofs, flat-roofed extensions, doors facing the street, boundary walls, dishes;
  per-building overrides for roof, wall, facade photo or 3D model
- Third person on foot: walk, sprint, jump, aim, shoot, reload, two weapons,
  slow-motion aiming, stamina
- Driving: cars and minibus taxis on vehicle physics, enter and exit, chase
  camera, headlights, horn, call your car back for R20
- Residents, police and a gang as factions, with wander, patrol and combat
- Dialogue trees with conditions and actions; two missions with goto, kill,
  talk and return steps; rands; reputation; wanted level with witnesses, decay
  and an admission-of-guilt fine
- Day and night, five weather states, generated textures and sounds, graphics
  quality tiers
- HUD, minimap, full map with waypoints and location names, pause menu with
  settings, one-slot save and load
- An automated smoke run that plays through the game and reports PASS/FAIL

Next, in order:

- SOLID refactor: unit test runner, service seams out of the singleton, step and
  action registries, retire the singleton, split simulation from presentation
- Then enhancements: house numbers and addresses, roofs for any outline,
  landmark models, animals, an Android build, more missions, multiplayer co-op

## 4. Data - What are we storing?

Everything is JSON on disk; there is no server and no database.

- `data/config.json` - which map folder to load
- `data/maps/chatsworth-unit7/world.json` and `heightmap.json` - generated by
  `tools/osm_to_map.py` from OpenStreetMap and elevation sources
- `npcs.json`, `dialogue.json`, `missions.json`, `weapons.json` - hand-written
- `overrides.json` - per-building looks keyed by OpenStreetMap id
- `user://save.json` - money, reputation, position, clock, dead NPCs, mission
  state, wanted level, health, ammunition (single slot)
- `user://settings.cfg` - mouse, volume, graphics quality

## 5. Tech - What stack are we using?

- Godot 4.7.2 .NET, Forward+ renderer on desktop
- C# on .NET 8 (`Godot.NET.Sdk/4.7.2`, nullable enabled, latest language version)
- `System.Text.Json` for all data files
- Python 3 (standard library only) for the map tools
- Git, hosted at github.com/violan7naidoo/veld

Constraints: Godot 4.7 cannot export C# to the web, so web waits for a later
Godot. Android and iOS C# export exist but are experimental; iOS needs a Mac.
The Mobile renderer lacks SDFGI, SSAO, SSIL and volumetric fog, which the Low
quality tier already turns off.

## 7. UI/UX - How should this look and feel?

Third-person over-the-shoulder camera, a minimal HUD (health, stamina, money,
compass with objective marker, minimap, interaction prompt), a dialogue box with
numbered choices, a full map on M, a pause menu. Box-and-cylinder placeholder
models for people, cars and props, meant to be replaced by real models.

Content rules (from `docs/design.md`): every character is invented; shops get
generic trade signs; real public places keep their names; missions are
small-town stories, not crime caricature; the area's Group Areas Act history is
acknowledged, not performed.

## 8. Deployment - Where and how will this ship?

- Now: Windows desktop, run from the Godot editor or `play.cmd`. No export
  preset configured yet.
- Planned: Android first (Google Play requires a 12-tester, 14-day closed test
  for new personal accounts), then iOS (Mac and Apple Developer Program).
- No server, no env vars, no cron. The app must show the OpenStreetMap and SRTM
  attribution.
